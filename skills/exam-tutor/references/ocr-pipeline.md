# 真题题库 OCR 扩充流水线（零 token 本地）

> 仅在给题库新增章节/新书时需要；日常出题不需要读本文件。
> 源书：某版题目册＋答案册（扫描 PDF 无文字层）。

## 新章流程

0. **定位章边界（OCR 前必做）**：
   - 先 grep 已有 raw 文本里有无新章章头——**新章标题常落在上一章已 OCR 的最后一页**（6600 第四章章头在 q088，而 q088 一直被当第三章尾页；3600 第四章答案起于 a_pdf026_L，与第三章尾页同文件）。上一章提取范围必须排除该边界文件里的新章内容。
   - **页码偏移每本书、甚至同书不同册都不一致，不许心算硬推**：6600 题本 印刷=PDF+5（q088=印刷83）但答案册 印刷=PDF+267；此前记的"印刷=PDF-6"与第四章实测冲突。用目录页印刷页码（6600 题本 TOC 在 p005、答案 TOC 在 a002）+ grep 章头双确认。
   - 目录里有章总题数（如"第四章教师与学生(260小题)"）和各专题印刷起页——用它估算 OCR 范围并作为最终题量验收标准。
   - OCR 范围宁多勿少：多扫几页再 grep 下一章章头裁界，比漏扫重跑便宜。
1. 切半页 OCR（题目册＋答案册）：venv=`<OCR项目>/venv`（RapidOCR；onnxruntime 必须锁 1.20.1 否则段错误）。3600 左右印刷页拼合**必须切半**（脚本参考 `<OCR项目>/split_ch23.py`）；6600 单页单栏无需切。两本书可写进同一个后台脚本顺序跑（参考 `<OCR项目>/ocr_ch4.py`），每页打印碰到的章头关键字；前一本跑完即可派该本子代理，不必等后一本 OCR。
2. grep 定位章节/题型/板块边界行 → 子代理并行提取。**边界写成 BOUNDARIES_chN.md 落盘**（模板 `<OCR项目>/raw66/BOUNDARIES_ch4.md`：每个专题×题型的 文件:行号 + 输出 schema），后续对账/补录会话靠它恢复。分工按书定：6600 每专题一个子代理（题本+对应答案页包干）；3600 按 夯实题目/能力题目/答案速查+解析索引 三代理。给子代理的边界要具体到文件清单+行号（板块标题在页内时尤其必要）。**派子代理时 goal/context 文本禁用英文双引号**——嵌套引号会让 tasks 的 JSON 解析失败（报 `tasks must be a JSON array ...`），引文一律改用中文引号或书名号。
3. 合并对账走**三通道**，只跑一条不算核过：
   - **解析行重建**：从答案本 `N.答案【解析】` 逐题重建 truth 再逐题比对（脚本 `<OCR项目>/merge_ch23.py` 按章节中文数字传参；6600 样例 `merge_ch66_v3.py`，3600 样例 `merge_ch4.py`/`merge_ch5.py`）。
   - **速查表拼接核对**：多选速查行连写时**不要猜着切分**——把该 range 内解析行答案按序拼成字符串，与速查串直接全等比较（一致＝整行通过；不一致的单点再裁决。实例：3600 第五章 31/31 一致；第四章唯一分歧是速查把 AA OCR 成 VV，视觉定案 AA）。
   - **题号普查**：按 章/专题/题型 收题本行首题号集合与提取集合做差，抓漏提取与缺尾；再用目录标称小题数做总验收。
4. 缺损抢救阶梯，**先零 token 后视觉**：
   - ① 目标页整页/半页 **scale 4 重扫**：scale 2 会整行丢字（页边、行尾裁切、装订处），放大到 4.0 常能整行还原。
   - ② 仍缺再**视觉读原页**：按渲染图比例裁小图喂 vision（整页图字太小）；**crop 位置常一次不中**——按该题在 OCR 行号里的相对位置估区间，出图发现是邻题就同页按比例挪，别在同一位置重复问。
   - ③ 原书句尾可能本来就没有谓语（如"……等的课程（ ）"），**照录不补词**，uncertain 注"原书原文如此"。
   - 定位题号别靠题号行——题号行本身就是最常丢的那一行：用**选项反查**（搜选项原文所在位置）或邻题题干定位。
5. 错字走词表 `<OCR项目>/错字修复词表.md`，apply_fix 落盘。

## 6600 特有坑（均已踩过）

- 题型标题正则必须含 `[一二三四五六七八九]`（专题二案例是第八节）。
- 答案速查表范围行与答案行分行（"1~5" 换行 "CABCC"）；多选行 OCR 常连写不可机读 → 视觉读原书速查页。
- 速查判断符号 `'<'` 实为 √ 非 ×（用已验证的解析行反推）。
- 部分论述/案例答案无 "1." 编号，无法机核 → 子代理对照解析 + 存在性 grep。
- 题本无 [年份] 来源标注。

## 3600 特有坑

- **判断速查符号不可用**：3600 判断速查行 OCR 成 `XXAAA`/`XAAAX`/混 `v` 之类，无法可靠解码 → 判断答案一律以解析行 √/× 为准，速查只用于单选/多选字母与数量校验。`'<'=√` 是 6600 的规律，别套到 3600。
- **速查行格式不统一**：多选行可能空格分隔（`ACD ABD ABC BCD AD`）也可能连写；单行范围（`71` + `D`）不匹配"两个数字"正则。展开器按 `[|,，/]|\s+` 切分，并跳过单行范围（由解析行覆盖）。
- **板块标题可能整行 OCR 丢失**（第五章能力提升练的"三、判断题"没了）：用答案册对应板块标题 + 题本首个带号题目反推板块起点，别因为缺标题就认定该板块不存在。
- **子代理给的 id 会按题型各自从头重排**（单选 1..n、多选又 1..n）→ 定稿时按 section 内出现顺序全局重编号并断言唯一（第五章 151 题只生出 114 个唯一 id）。

## 定稿卫生（finalize）

- 修复字典一律用 `(section, qtype, num)` 三元组作键：只用 `(qtype, num)` 会让"夯实判断12"和"能力判断12"互相覆盖（第五章踩过，能力判断12 被写成夯实题）。
- 克隆上一章的 merge/finalize 脚本时逐条改文件名与输出路径，**改完 grep 一遍旧名确认全部替换**（曾把第五章合并结果 dump 回 ch4_merged.json 且不报错）。
- 质量分级看题干与选项本身：恢复完整的＝usable（uncertain 里写着"丢失"不算数）；以"……"开头、占位、选项含 null、过短的＝broken。定稿后打印 broken 清单逐条确认，能救的一律救到 0。

## 落盘后

- 题量/题型分布/质量结论写进 SKILL.md「真题题库（已入库）」小节；quality 分档 ok/usable/broken，quality!='ok' 不进模考卷。
- 分档看**题干本身**而非 uncertain 记录：据解析重建出完整题干的＝usable（不因记录里出现"丢失"就判 broken）；题干以"……"开头/缺页占位/过短的＝broken。先粗分再用脚本精修（参考 `<OCR项目>/regrade66.py`），并对照目录总题数验收（各专题题号普查 1 连续、章总数吻合）。
