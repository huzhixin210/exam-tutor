# 数据格式

## 题库 JSON

`make_quiz.py` 按文件名找题库：`<章节>.json`（主教材，40%）和 `6600_<章节>.json`（补充，60%）。

顶层可以是裸数组，也可以是带 `questions` 字段的对象（推荐后者）：

```json
{
  "chapter": "第一章",
  "source": "你的题库来源（写给自己看）",
  "total": 6,
  "questions": [ ... ]
}
```

每道题：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 全局唯一，脚本靠它去重/记已做/记弃用 |
| `qtype` | ✅ | `单选` / `多选`（多选占 25% 左右，靠它识别） |
| `stem` | ✅ | 题干，**不要**带选项，不要带答案 |
| `options` | ✅ | 对象 `{"A": "...", "B": "..."}` 或数组 `["...","..."]` |
| `answer` | ✅ | 单选 `"B"`，多选 `"ACD"`（大写、连写、逗号都行，脚本原样输出） |
| `kp` | ✅ | 考点名，用于「同考点最多 2 题」和专项复习匹配 |
| `analysis` | 建议 | 解析。批改时 AI 用它给讲解 |
| `tags` | 建议 | 数组，如 `["易错"]`、`["清单"]`；组卷时优先抽有 tag 的题 |
| `quality` | 可选 | 非 `ok` 的题会被跳过（`"quality": "bad"` 等于临时弃用） |
| `section` / `topic` / `num` | 可选 | 原书出处，保留便于回溯 |

**易错点**：
- `answer: null` 的题一定要补，否则 AI 判分只能靠猜（脚本会把 `None` 原样写进 `当前批次.json`）
- `options` 里不要有 `null`（脚本视为残缺题跳过）
- 选项别自带 `A.` 前缀，虽然脚本会剥，但容易出错

## 掌握度 JSON

```json
{
  "说明": "...",
  "更新日期": "2026-11-05",
  "章节": {
    "第一章第一节_教育及其产生发展": {
      "考点1_词源与词义": {
        "掌握度": 65, "答题数": 4, "错题数": 1,
        "最近复习": "2026-11-05", "跨日对次": 2, "next_review": "2026-11-12",
        "档位": 2, "证据数": 2, "上次复习": "2026-11-05", "连续错": 0
      }
    }
  }
}
```

键名格式：`<章>第<节>节_<节名>` → `考点N_<考点名>`。**找不到精确匹配就新建键，不要塞进"最相近"的旧键**——塞错会让两个考点共用一份数据，最弱考点排序全失真。

## 进度 JSON

见 `template/做题系统/进度.json`。关键是 `last_session_closed` 和 `当前阶段`：新会话读这两项就能恢复上下文，不必翻全部历史。

## 批次记录 JSONL

每批一行，**只追加不覆盖**：

```json
{"date":"2026-11-05","batch":78,"chapter":"第四章","items":[{"no":1,"id":"ch4-01-001","answer":"B","kp":"职业性质"}],"answers":"A,B,C...","score":"8/10"}
```

新会话读最后 3–5 行就知道"刚做的几批是什么、错在哪"，约 200 token。
