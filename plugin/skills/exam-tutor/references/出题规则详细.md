# 出题规则 · 详细版

> 主 SKILL.md 只保留摘要；出题前需要细节时读本文件。

## 出题规则
- **全部从3600/6600题库出题，不再自出背诵稿题**（2026-10-24 用户定）：配比 **3600真题 4道 ＋ 6600题库 6道**；背诵稿仅用于出题前核对考点原文（防编题）；**每题批改时标注对应背诵稿考点**（如「考点6 教育制度·四特点」），方便用户对照复习
- 题型配比按真题：单选为主，穿插多选/判断/填空；一批10题混合考点
- **批次配比（2026-10-24 定）：默认批＝6道到期复习＋4道新考点（复习:新＝6:4）**。6道从 next_review 到期池抽（错题 next_review=次日天然入池，原"每批带1-2道错题"并入此池）；新题从背诵稿已学范围出（学习记录.md 说学到哪就出到哪）。**复习题跨章节混出、不搞复习专项批**——用户失分大头是配对串位/最早互换，只有混着练才拆得掉"章节线索"这根拐杖；错题积压>15 则整批改出错题复习
- **用户可点名的整批范围批**：学完一个新节当天，或用户直接说「出一批第X章第X节的题」，就整批 10 题全出该范围（含 1-2 道换壳），计入当日题量，发题时一句话说明本批覆盖哪节；平时不主动出专项，用户点名就照办（别拿「唯一出专项的情形」挡回去）
- **当日总量目标**：用户报「今天做50道」「一章二章各25道」这类总量时，按 10 题/批拆成若干批并**每批批改后报一行「今日进度 X/50」**，做完即提醒切换（如「上午两章、下午第三章」）并把排期写进进度.json 的当前阶段——不要只做一批就当交差；用户中途说总量变了以最新数字为准
- **错题重做不得原题照搬**（2026-10-18 用户反馈）：必须换问法/换选项顺序/换情境，考点不变题面变
- **错题必须销账，不能只追加**：换法重做答对后，在该错题条目末尾追加一行「✅已销账（YYYY-MM-DD）」，并从进度.json 待重做清单移除；「错题积压>15 改出整批复习」的判据只数**未销账**条目——不销账则错题本只增不减，阈值一触发就整天刷旧题、新考点排不进；超纲作废题另标「⚠作废」，与销账分开记
- **题号后不得标注考点名**（2026-10-18 用户反馈）：如「考点12·王守仁」会把答案人物直接写在题干前泄露出来；只标题型和来源（如「单选·真题2025山东」）
- 出题前读背诵稿对应考点原文核对（禁止凭记忆选考点或写批改要点，但题目本身全部来自题库）；读之前先 glob `教编备考/背诵/` 拿真实文件名——**背诵稿会被拆分/重命名**（第三章曾从2节拆成4节，硬编码旧文件名直接 FileNotFoundError），章节归属以文件头部「章节归属」声明为准
- **新章首次出题前先 glob `做题系统/题库/` 确认 3600 与 6600 两个文件都已入库**：题库可能由用户在自己另开的会话里 OCR 建（用户会说「第四章好了」），只一侧入库时按实际存在的一侧出题并在发题时一句话说明配比调整，不要凭「章节已学」假设题库齐全；该章未入库就先出上一章收尾批或错题专场，等用户说入库再切
- 出题结尾不要写「回复如 1B 2B…」之类的作答示例（2026-10-18 用户反馈：示例会把正确答案带出来），只说直接回复答案即可
- **新章未入库却被点名要做题时（第五章及以后常见）**：先 glob 题库确认该章 3600/6600 都不存在，然后**不要默默自出题**也不要直接拒绝——一句话告知「该章题库尚未 OCR 入库」，给两个选项：①先 OCR 入库（走 references/ocr-pipeline.md）②本批从背诵稿自出 10 题应付当下、并标注「自出题，非题库题」（这批不进 `asked_ids`、不进模考口径，下批题库到位后重出覆盖）。等用户点头再动手。**再加一条并列选项（用户实际最常选的）**：③**并行**——把该章题库 OCR 丢给另一个会话后台跑，本会话继续用已入库的章出题，进度不断档；题库一入库就切回真题并在发题时一句话告知切换。给出选项时优先提③，它既不待工也不降质量
- 题库筛选要一次性批量提取（一个 execute_code 调用取齐全部所需题），不要逐题查询（教训：逐题查16次导致出题延迟3分钟以上）（背诵稿整读一次即可覆盖全节，不必每题重读）；**凑 3600×4 时一次打完候选**：筛题调用里 3600 与 6600 各打印 6-10 道未 asked（含题干/选项/答案），别按考点组反复筛——一次只印 3-4 道会导致为凑满 4 道 3600 连开三四轮筛题，纯烧调用
- **题库余量核检（每章首刷与后期都要做）**：每批筛题时顺手打印「本章 3600 未 asked 剩余 N 道」，N<10 时在发题消息里一句话告知用户「本章3600基本刷完，后续以6600为主、配比调整为…」，别等筛到 0 才发现；3600 刷完的章把该章 6600 当主力并说明；**若该章 3600 已空但 6600 仍充足，3600×4 改为从已学过的旧章题库补（优先历史欠账钉子所在章），发题时一句话说明「本章3600已刷完，本批3600取自第X章钉子」，不要为了凑配比去出背诵稿题或重复已发过的原题**
- **第四章固定规则（2026-10-27 用户定）**：第四章.json（3600，133题）已全部刷完 → 后续批次固定组卷＝「**其他章节的 3600（优先欠账钉子所在章）＋ 第四章的 6600**」，不再从第四章.json取题；6600_第四章存量约150道可用
- **一批题一次备齐再发（出题全程≤1次工具调用）**：在单次 execute_code 里同时完成：题库关键词过滤（options 兼容 dict/list）→ 按考点索引+字符偏移切片读背诵稿对应段落 → 打印全部题干/选项/答案/解析摘要，然后立即发题。逐题或分多段取材会让用户干等并抱怨思考耗时（2026-10-20 用户两次反馈"思考太占用时间"，一次调用取齐后显著提速）；配比与选题规则都已定死，不再在思考里重新权衡，机械执行即可
- 用户说「某节前半/后半」＝按背诵稿骨架的板块边界对半切（如第一章第二节前半＝板块一~三：教育学概念＋中国古代＋西方古代），发题时用一句话说明本批覆盖范围
- 批改格式：表格（题号/答案/✓✗/批改要点/**对应背诵稿考点列**）+ 每错题给「出处（考点+必背条目）+└解记忆抓手」；**每批对错数一律用代码统计（len(right)/题数）后再写进批改首行，不心算**——心算曾把「6对4错」报成「4对6错」，用户会照着错数字判断自己状态；**错题条目开头必须带醒目标签【考点标记】第三章第三节·考点X 考点名**（2026-10-24 用户定，方便日后重点背诵）；用户点名要「讲解」时用**全家福表**。解析用户答案按题号位置对齐，容错常见格式：V/X＝√/×、中英文逗号句点混用（"B.D"＝第5题B第6题D）、答案 token 多于题数时多出的视为对前一题的改答（批改表里标注）、少于题数的缺项按「?」未答处理；**串里自带「第五题开始…」这类起点标记时，按标记从该题起对齐**，前面的题先问一句是漏答还是上一批的补答，别按位置从头强对。**但作答与题型不匹配时先追问再落盘**：单选题却给了多个字母、或作答数明显少于题数（用户中途漏题）——位置对齐必然错位，先把批改表按对齐结果发出去并问一句「第N、M题是漏答还是不会？」，得到确认后再更新掌握度/错题本；**反过来，答案个数明显多于本批题数时不要按位置硬对**——先看它是否正好等于某份「已发出待作答」大卷的题数（月考20、周测10）：匹配则按那份卷批改、并在进度.json 把该卷标完成（用户常把上一天领的大卷答案直接贴过来，当成刚发的小批去对会错位）；已记错的要双向撤回（误记错的：掌握度+15、错题数-1、错题条目头部加「⚠作废」更正行），不要靠沉默覆盖。判据：他补答后往往会得到「其实全对」的结论，撤回成本远高于多问一句。
- **用户答「?」＝不会/空题**（2026-10-21 用户改定）：**答案序列里的**「?」一律当错题处理——掌握度按错更新、入错题本（标注「未答」错因＝不会）；批改时直接给答案+一个记忆抓手，下批换法重考。但**整条消息只有一个「?」、不在答案序列里**＝催我继续（上一轮被打断或没看到回复），不是作答，不要当错题记录，直接接续被打断的批改/发题
- 全家福表的用法：把整个易混人物群拉成一张表（人物/观点/关键定位，如所有谈"自然"的教育家：亚里士多德最早→夸美纽斯根本原则→卢梭自然主义→福禄贝尔幼儿天性→裴斯泰洛齐自然法则→道家大自然→赫尔巴特没提），并顺带回答引出的追问（如"无目的论还有谁"→只有杜威，附邻近概念家族）
- 用户抱怨"题太难/没学过"时：先说明题目全是真题原题（题干后的年份+省市标签即证据，人物↔著作↔名言对应就是真题主考法），再按背诵稿★级说明该考点考频（★低的混错不亏），不改难度只做预期管理
- **用户质疑题目出处/怀疑幻觉**（如"这个考点我怎么没听说过"）：不空口自证——一次 execute_code 同时 grep 背诵稿＋网课总结，贴出**行号＋必背条目原文＋网课时间戳**（网课总结里带"（63:05）"类视频时间），双文件交叉验证最有说服力；顺带说明该考点为何没印象（新扫章节/二级考点未考过）
- 用户可临时调章节权重（如"多出第二章、第一章少些"）：2:3:5 来源配比不变，只调整各来源里的章别抽题范围，并在发题时一句话说明本批覆盖范围
- 用户在答案文本里顺口点名要讲某个点（如"稷下学宫给我讲一下我忘了"，即使该题答对）→ 直接在批改消息里补讲解，不额外调工具。**点名要「讲一下×××（某个知识类）」时给完整框架而不是只讲那道题**：从该章背诵稿的板块骨架提取全部分类组，做成表格（分类标准｜各组定义｜典型例子）＋背诵稿原文口诀（如课程类型六组＝学科/活动·分科/综合·显性/隐性（一级）＋必修/选修·国家地方校本·基础拓展研究（二级）；综合课程四形式口诀「关心荣誉」），再回头点出该题落在哪一格——用户要的是「心里有框架」，不是单题解析
- 批改后立即更新掌握度和错题本——**必须实际完成工具调用后再回复用户**，严禁只在回复里写「已更新/已入本」而没跑工具（曾漏记一整批10题的掌握度、错题16-19 声称已写实未写，隔很久才发现需要回补）；掌握度和错题本的写入放在同一次批改流程里，并在同一次调用里顺手更新进度.json（更新日期/待重做错题/欠账考点/下一步计划），先写文件再发批改消息
- **错题本追加后必须回读验证编号连续性**：append 返回 success 不等于内容落盘（错题103/104/105 曾整段消失，后续批次编号从102直接跳到106，多批之后才发现缺号）。写入后同一次调用内 `re.findall(r"### 错题(\d+)", 错题本全文)`，打印尾部编号确认**连续且末尾编号＝本轮最后一个**；发现跳号立即按原内容补写插回正确位置（插到下一编号条目之前，不要追加到文件末尾）


## 统计与收官报告要点
- 统计口径以掌握度.json 的答题数/错题数为准（逐批心算容易和文件漂移），先聚合再汇报
- 错题分析按**知识簇**归并（如「自然家族」「称号之父vs代表」「最早类互换」），不只逐考点列表——用户要的是失分模式，不是流水账
- 收官报告存 `学习报告_YYYY-MM-DD.md`，结构：分批走势表 / 错题簇表 / 掌握度现状（≥70、60-65、<60欠账三档）/ 错题本重点 / 明日计划；**当天报告若已存在，先 read_file 全文再决定写法**：若是另一会话（企微）写的，必须读全文后**合并**——保留对方的分批表与错题表，本会话部分另起一节，开头加「两个会话合并」总计表；只有确认是自己的旧版才可整篇覆盖（write_file 对未读过的文件有防覆盖拦截，跨会话覆盖会直接抹掉手机端记录）
